- 本地父目录已从 codexcctv 改为 codex-eyes；源代码仍位于其中的 coding 目录。

- 使用已登录的 GitHub CLI 从 Release 重新下载 DMG、ZIP、SHA-256，校验通过。
- 从下载的 DMG 安装到 `/Applications/Codex Eyes.app`，实际运行进程已确认来自该位置。
- 安装后的嵌套签名完整性和包内账号辅助程序的合成账号测试通过。
- 原有两个账号、备注、语言、外观与快捷键保留；开机启动在安装版恢复为启用。
- 实际检查账号查看切换、额度与累计读取、用量详情、总览热力图和全局快捷键。
- 相关客户端运行时，真实登录切换被拦截；取消后保持原账号。测试前后 auth.json 校验一致。
- 迁移后的源码在全新构建目录运行69项测试，全部通过。
- 新安装版的10条任务 Hooks 已指向安装位置，旧开发路径不再被引用。

## 尚未确认的范围

- 新路径的任务 Hooks 尚未观察到新的任务事件，不能用历史“已收到”状态证明已完成重新信任。
  需用户在 Codex 的 `/hooks` 中审查新命令并信任，再运行一轮任务验证。
- 系统通知权限沿用用户原本关闭的状态，没有申请新权限或测试通知横幅。
- 没有退出当前 Codex/ChatGPT 客户端，也没有执行真正的账号登录切换。
- 当前包未经过 Apple Developer ID 公证。GitHub CLI 下载测试不等同于浏览器下载后的
  Gatekeeper 首次启动验收；后者仍可能受到系统验证限制，没有移除隔离属性或关闭系统保护。
- Intel、macOS 14 实机仍需对应硬件/系统验证。

自动构建模板保存在 `docs/workflows/`，没有为初次上传扩展 GitHub OAuth 的 workflow 权限。
